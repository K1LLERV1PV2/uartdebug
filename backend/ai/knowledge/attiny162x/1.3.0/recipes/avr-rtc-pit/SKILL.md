---
name: avr-rtc-pit
description: Configure RTC.PIT periodic interrupts from INT32K during one-time startup on ATtiny1624/1626/1627.
---

Use this recipe only for PIT interrupts from the internal nominal 32768 Hz source, initialized once after reset and before global interrupts are enabled. Reserve the RTC instance, its shared clock/correction configuration and RTC_PIT_vect; provide exactly one handler. The RTC counter remains disabled. No other initialization or owner may have started RTC/PIT or changed their shared configuration before this setup.

Describe the resource with kind `rtc-pit`, instance `RTC`, clockSource `INT32K` and an explicit periodCycles value. For the nominal 125 ms example, use periodCycles `4096` and periodUs `125000`; periodUs may be null when periodCycles alone specifies the interval. If periodUs is supplied, it must agree with the chosen cycles. Add the GPIO resource separately and resolve its pin against the exact device/package and board connection. With spec.clock.hz=null, leave the CPU clock unchanged and make no CPU-frequency or cycle-timing claim. PIT does not need F_CPU, a guessed reset CPU frequency, CLKCTRL writes, or fuse changes. If another resource needs a known CPU/peripheral clock, resolve that resource through its own reviewed recipe.

Choose periodCycles only from the powers of two 4 through 32768 and use the matching `RTC_PERIOD_CYC<n>_gc` symbol from the pinned device header. OFF and the reserved PERIOD value are not operating periods. Nominal periodUs = periodCycles * 1000000 / 32768; for 4096 cycles this is exactly 125000 us as a mathematical configuration. Retain fractional microseconds when necessary instead of claiming a rounded value is exact. This is a nominal oscillator calculation, not measured real-time accuracy. Do not silently substitute an unsupported interval; report the supported selection and its difference from the request.

Initialize dependent GPIO and shared software state before enabling interrupt delivery. For an active-low LED, set OUTSET before DIRSET so the initial output is off. With both RTC.CTRLA.RTCEN and RTC.PITCTRLA.PITEN still zero, explicitly select `RTC.CLKSEL = RTC_CLKSEL_INT32K_gc`. This disabled-state requirement is the recipe's startup contract for protecting the shared clock, not a claim that the register enforces it. Leave RTCEN, CORREN, calibration and debug configuration at their reset state. Do not silently stop or reconfigure a running owner to satisfy this precondition.

Clear PI by `RTC.PITINTFLAGS = RTC_PI_bm` before enabling `RTC.PITINTCTRL = RTC_PI_bm`. Immediately before writing PITCTRLA, wait until `(RTC.PITSTATUS & RTC_CTRLBUSY_bm) == 0`. Write the selected PERIOD symbol and `RTC_PITEN_bm` together, then wait for the same busy flag to clear before depending on completion. PIT uses PITSTATUS, not RTC.STATUS. Do not replace synchronization with a delay. Enable global interrupts only after all peripheral initialization and shared state are ready.

In `ISR(RTC_PIT_vect)`, acknowledge PI first with the direct write-one-to-clear assignment, then perform only short bounded work. Do not use `|=` to clear PI or assume vector entry clears it. A GPIO toggle is appropriate; lengthy processing belongs in main. If main consumes ISR data, apply the existing volatile, atomic-access and ownership rules. PI is a one-bit pending flag: multiple occurrences can coalesce while interrupts are masked or service is too slow. Assess service latency separately; the oscillator period alone does not prove that every occurrence is handled.

The RTC/PIT prescaler has shared phase. The first PIT condition after enable can occur almost immediately or after one full selected period; enabling does not establish a fresh zero phase. For 4096 cycles, the nominal first-condition delay is approximately 0..125 ms. GPIO transitions also include synchronization and interrupt-service latency. Subsequent uninterrupted hardware conditions have the selected nominal period. With reset debug settings, a halt/resume can introduce an extra PIT condition; debugger stepping is not timing evidence.

Scope excludes the RTC counter, alternate clocks, frequency correction/calibration, sleep entry, EVSYS, and runtime stop/reinitialization. Those require separate review. Sources: DS40002234B sections 23.5.1/2, 23.6, 23.10/11 and 23.13.8/12-15 (pages 268, 270, 272, 281, 285-288); pinned DFP register and vector definitions. DS80000902F has no RTC-specific silicon issue, which does not prove hardware validation. Lineage: colleague Project_One PIT blink; this recipe adds explicit clock ownership and flag initialization.
