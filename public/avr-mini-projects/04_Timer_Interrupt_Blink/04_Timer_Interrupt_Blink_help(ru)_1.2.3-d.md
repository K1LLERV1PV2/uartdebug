# 04_Timer_Interrupt_Blink
Мигание светодиода по прерыванию таймера

## File Version
Версия файла

Version 1.2.3-d

## Short Project Description
Краткое описание проекта

Неблокирующее мигание светодиода с использованием периодических прерываний переполнения TCA0.

## Full Mini-Project Description
Полное описание мини-проекта

Этот мини-проект настраивает 16-разрядный таймер TCA0 для создания прерывания переполнения примерно каждые 0,5 секунды.

Внутри обработчика прерывания состояние PB1 переключается. Поэтому светодиод, подключённый к PB1, изменяет состояние при каждом прерывании. Один полный цикл включения и выключения занимает примерно 1 секунду.

В отличие от реализации с программной задержкой в мини-проекте 03, эта программа не удерживает главный цикл внутри функции задержки. Главный цикл остаётся доступным для прикладного кода, хотя кратковременно прерывается при каждом запуске обработчика таймера.

### User-Defined Timer Parameters
Параметры таймера, задаваемые пользователем

`F_CPU` задаёт частоту процессора, используемую при расчёте периода таймера. При заводских настройках тактирования это значение равно `3333333UL`, то есть приблизительно 3,333 МГц. Эта директива не настраивает аппаратную частоту.

`TCA_PRESCALER` — числовой коэффициент деления тактовой частоты таймера, выбираемый пользователем. Он должен быть одним из значений делителя, поддерживаемых TCA0. Выберите его так, чтобы рассчитанное значение `TCA_PER_VALUE` помещалось в 16-разрядный регистр `PER`. Слишком малое значение `TCA_PER_VALUE` уменьшает доступное разрешение по времени.

`TCA_PERIOD_US` — требуемый интервал прерывания таймера в микросекундах. Это значение задаётся пользователем.

`TCA_PER_VALUE` — значение, записываемое в регистр периода таймера. В этом мини-проекте оно автоматически рассчитывается по `F_CPU`, `TCA_PRESCALER` и `TCA_PERIOD_US`.

При выбранных параметрах фактический интервал прерывания составляет приблизительно `0,4998 с`.

## Hardware Requirements and Setup
Требования к оборудованию и подключение

Требуются светодиод и подходящий токоограничивающий резистор.

Подключите цепь светодиода к `PB1` с учётом полярности выбранного варианта подключения.

Для ATtiny1624 в корпусе SOIC-14 сигнал `PB1` находится на выводе 8.

## Quick Start
Быстрый запуск

1. Подключите светодиод и токоограничивающий резистор к `PB1`.
2. Скомпилируйте и прошейте мини-проект.
3. Наблюдайте за светодиодом.
4. Светодиод должен изменять состояние примерно каждые 0,5 секунды.
5. Полный цикл мигания должен занимать примерно 1 секунду.

Правильная работа подтверждает совместную работу TCA0, прерывания переполнения, ISR, глобального разрешения прерываний и выхода PB1.

Для ATtiny1624 в корпусе SOIC-14 подключите цепь светодиода к выводу 8 (`PB1`).

## What This Mini-Project Is For
Для чего предназначен этот мини-проект

Этот мини-проект демонстрирует:

- периодические прерывания таймера TCA0;
- неблокирующее формирование времени;
- структуру обработчика прерывания;
- управление GPIO из ISR;
- глобальное разрешение прерываний с помощью `sei()`;
- сохранение главного цикла доступным для другой работы.

Он может служить основой для периодических фоновых задач, которым не требуется блокирующая программная задержка.

## Usage Options
Варианты использования

Можно:

- изменить `TCA_PERIOD_US`, чтобы выбрать другой период прерывания;
- выбрать другой поддерживаемый предделитель TCA;
- перенести выход на другой вывод GPIO;
- заменить переключение светодиода другой короткой периодической операцией;
- добавить прикладной код в главный цикл, включая код, блокирующий главный цикл, при условии, что он не отключает глобальные прерывания.

При изменении частоты процессора обновите `F_CPU`.

Обработчики прерываний должны оставаться короткими. Не используйте внутри ISR блокирующие задержки и длительные вычисления.

## Code Description
Описание кода

### Main Compiler Header
Основной заголовочный файл компилятора

`#include <xc.h>` предоставляет определения регистров и битов конкретного устройства, используемые компилятором XC8.

### Interrupt Header
Заголовочный файл прерываний

```c
#include <avr/interrupt.h>
```

Этот заголовочный файл предоставляет макрос `ISR()` и функцию `sei()`.

### CPU Clock Definition
Определение частоты процессора

```c
#define F_CPU 3333333UL
```

`F_CPU` задаёт частоту процессора, используемую при расчёте периода таймера. При заводских настройках тактирования это значение равно `3333333UL`, то есть приблизительно 3,333 МГц.

Эта директива не настраивает аппаратную частоту.

### Timer Configuration Parameters
Параметры настройки таймера

```c
#define TCA_PRESCALER 1024UL
#define TCA_PERIOD_US 500000UL
```

`TCA_PRESCALER` — числовое значение выбранного делителя тактовой частоты TCA0.

`TCA_PERIOD_US` — требуемый период прерывания в микросекундах.

Более подробная информация приведена выше в разделе **Параметры таймера, задаваемые пользователем**.

### Timer Period Register Calculation
Расчёт регистра периода таймера

```c
#define TCA_PER_VALUE     ((uint16_t)(((F_CPU / TCA_PRESCALER) * TCA_PERIOD_US) / 1000000UL - 1UL))
```

Это выражение рассчитывает значение, записываемое в 16-разрядный регистр периода TCA0.

Результат должен помещаться в 16-разрядный регистр `PER`.

Целочисленная арифметика округляет результат до целого количества тактов таймера, поэтому фактический период может немного отличаться от требуемого.

При значениях, используемых в этом мини-проекте, расчёт корректен. При существенном изменении параметров также убедитесь, что промежуточные вычисления остаются в допустимом диапазоне.

### TCA0 Initialization
Инициализация TCA0

`Init_TCA()`:

- выбирает обычный режим счёта;
- разрешает прерывание переполнения TCA0;
- загружает рассчитанное значение периода;
- выбирает деление тактовой частоты на 1024;
- запускает TCA0.

Числовое определение `TCA_PRESCALER` и аппаратная константа выбора тактовой частоты должны описывать один и тот же делитель.

### TCA0 Overflow Interrupt
Прерывание переполнения TCA0

```c
ISR(TCA0_OVF_vect)
```

Размещайте здесь короткий код, который должен выполняться при каждом прерывании таймера.

В этом мини-проекте единственное прикладное действие внутри ISR — переключение выхода PB1.

#### TCA0 Overflow Interrupt Flag Reset
Сброс флага прерывания переполнения TCA0

Флаг прерывания переполнения не очищается автоматически. Его необходимо очистить внутри ISR записью `1` в бит флага. В противном случае запрос прерывания может остаться активным и вызвать немедленный повторный вход в ISR.

```c
TCA0.SINGLE.INTFLAGS = TCA_SINGLE_OVF_bm;
```

Обратите особое внимание на эту операцию: бит флага, установленный в `1`, очищается записью `1` в этот бит.

### The Entry Point
Точка входа

`int main(void)` — точка входа программы.

### PB1 Output Initialization
Инициализация выхода PB1

```c
PORTB.OUTCLR = PIN1_bm;
PORTB.DIRSET = PIN1_bm;
```

Перед переводом PB1 в режим выхода устанавливается низкий уровень. Это задаёт определённое начальное состояние выхода.

### Timer Initialization
Инициализация таймера

PB1 настраивается до запуска таймера, потому что PB1 переключается внутри ISR таймера.

```c
Init_TCA();
```

После возврата из `Init_TCA()` таймер TCA0 уже работает, но его прерывание не может быть обработано до глобального разрешения прерываний.

### Global Interrupt Initialization
Глобальное разрешение прерываний

Глобальные прерывания необходимо разрешить, чтобы прерывание TCA0 могло быть обработано.

```c
sei();
```

Вызывайте `sei()` после завершения всех инициализаций, разрешающих источники прерываний.

### Main Infinite Loop
Главный бесконечный цикл

Цикл `while (1)` обеспечивает непрерывную работу программы.

В этом мини-проекте цикл пуст, потому что периодическое управление светодиодом выполняется ISR таймера.

В цикл можно поместить прикладной код, включая код, блокирующий главный цикл. Разрешённые прерывания всё равно смогут прервать такой код при условии, что он не отключает глобальные прерывания.

Код главного цикла и ISR не выполняются процессором одновременно. При возникновении прерывания процессор временно приостанавливает код главного цикла, выполняет ISR, а затем продолжает прерванный код.

### Main-Loop Application Code
Прикладной код главного цикла

Прикладной код можно размещать внутри главного цикла.

Примерно каждые 0,5 секунды ISR таймера временно прерывает выполнение кода главного цикла, а затем возвращается к нему. Обычно это прерывание длится очень короткое время по сравнению с интервалом таймера.

### This Code Is Never Reached
Этот код никогда не выполняется

`return 0;` не достигается при нормальной работе, поскольку выполнение остаётся внутри бесконечного цикла.
